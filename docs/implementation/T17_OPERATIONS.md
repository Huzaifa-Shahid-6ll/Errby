# T17 operations and privacy controls

The live model adapter still rejects every request. No paid provider call is enabled by this task. `model_budget` starts empty and has no client policy. A service operator must explicitly insert a reviewed cap and enable it before `reserve_model_cost` can succeed. The function serializes reservations across workers, stops when committed cost would exceed 90% of the cap, and permits at most two unsettled calls. Identical request keys replay; conflicting reuse fails. `settle_model_cost` is idempotent and records actual tokens/cost. A provider failure with known billed usage must settle as `failed` with that usage. An ambiguous provider outcome must remain reserved and count against the cap until reconciled; a TTL is diagnostic, never automatic permission to spend again. The caller must bound requests so actual cost cannot exceed its reserved maximum.

Live account deletion is available on `/setup`. It requires current Auth identity, same origin and explicit `DELETE` confirmation. Auth deletion cascades learner data through foreign keys; teachers with classes are blocked to avoid removing class content and learner sessions. No source binaries are currently persisted to Storage. The cost ledger remains with its owner reference cleared. General application logs contain no prompt or chat payloads; provider integration must preserve that boundary.

`expire_learner_records()` is a service-only maintenance function. It redacts raw conversation text, evidence quotes, interventions and event metadata after 30 days, closes old unfinished sessions, and deletes session records after 90 days. It is not scheduled automatically; an operator must arrange and verify a daily run in a hosted project before claiming retention is enforced. The retained 30–90 day assessment structure contains verdicts and objective IDs for summaries. This is a proposed default pending school/lead policy review.

PGlite checks validate migration/role controls and budget idempotency. They do not verify hosted Supabase Auth, Storage, provider billing, live concurrency or scheduled retention. Synthetic hosted acceptance must test Auth deletion, role isolation, class blocking, actual bill reconciliation, concurrent reservations and cleanup. No real pupil data is suitable until provider zero data retention and school requirements are confirmed.
